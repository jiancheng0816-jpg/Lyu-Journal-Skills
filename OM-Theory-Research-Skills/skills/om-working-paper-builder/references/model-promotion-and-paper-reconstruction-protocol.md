# Model Promotion and Paper Reconstruction Protocol

Use this protocol after the model auditor has produced a verified proposition-level result inventory.

## 1. Identify the paper's real mechanism

Write one causal chain:

`institutional primitive -> opposing forces/constraint interaction -> endogenous behavior -> equilibrium consequence -> design implication`.

If the existing main model cannot instantiate this chain directly, the paper hierarchy is not yet stable.

## 2. Rebuild the headline set

Use only results that passed correctness and novelty gates.

Preferred ordering:

1. Core mechanism result.
2. Equilibrium consequence.
3. Design/contract response.
4. Optional major extension with a genuinely distinct second mechanism.

Do not lead with a threshold or optimal ratio if the mechanism appears later.

## 3. Promotion/demotion decision

For every existing formal result decide whether it should become:

- headline;
- core mechanism lemma;
- equilibrium consequence;
- benchmark;
- design implication;
- extension;
- robustness;
- appendix;
- merge/delete.

A result's new role is determined by mechanism and novelty, not original numbering.

## 4. Promote the mechanism-bearing model

Promote a later model when:
- it is the first place the key behavior is endogenous;
- it changes interpretation rather than only parameters;
- it makes the Introduction's contribution statement literally true;
- the old main model only generates an aggregate proxy of the claimed behavior.

## 5. Demote tractability-only models

Demote a model when:
- its main advantage is a closed form;
- it is a special case;
- it is close to established literature;
- it hides the core behavior;
- it is best used to isolate one force.

Retain it as a benchmark or closed-form specialization when it still adds intuition.

## 6. Give every benchmark a job

Examples:
- no moral hazard -> isolate insurance;
- no financing friction -> isolate incentive effect;
- exogenous quality -> isolate risk sharing;
- closest-paper design -> show which institutional separation removes the new conflict.

Delete algebraic benchmarks with no narrative job.

## 7. Build the paper in mechanism order

Default structure:

1. Introduction.
2. Institutional background and closest literature.
3. Main mechanism-faithful model.
4. Benchmarks.
5. Core mechanism.
6. Equilibrium/campaign/market consequences.
7. Design or contract architecture.
8. Major extension.
9. Managerial and policy implications.
10. Conclusion.
11. Appendix / electronic companion.

Reorder when logical dependency requires it, but keep the mechanism visible.

## 8. Write propositions cumulatively

Use:

`Lemma -> interpretation -> Proposition -> mechanism -> implication -> boundary`.

A lemma should prepare the force used in the proposition. A proposition should change understanding, not merely introduce a formula.

## 9. Preserve conditional/aggregate distinctions

Always distinguish:
- conditional outcome;
- participation/entry/funding;
- aggregate realized outcome.

Do not claim a conditional operational distortion if the model only changes the extensive margin.

## 10. Use closest literature structurally

For each closest paper state:
- its friction;
- its instrument;
- what it holds fixed or protects;
- what assumption removes the present mechanism;
- whether its design can serve as a benchmark architecture.

This often yields a stronger contribution than a superficial "different setting" contrast.

## 11. Introduction consistency gate

Before finalizing the Introduction, verify:
- every headline claim appears in the main model;
- every headline has a verified proposition;
- every novelty claim has a closest-paper contrast;
- no demoted result remains advertised as a contribution;
- no extension-only mechanism is presented as if it were in the baseline.

## 12. Final reconstruction map

Deliver:

| Existing item | New role | Reason |
|---|---|---|

Then state:
- new one-sentence paper mechanism;
- headline order;
- benchmark jobs;
- main design/extension result;
- appendix moves;
- deleted or weakened claims.
