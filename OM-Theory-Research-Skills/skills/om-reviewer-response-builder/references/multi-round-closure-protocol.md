# Multi-round closure protocol

Use this protocol for a second or later review round, especially when the paper is described as moving toward acceptance but one scientific hurdle remains.

## 1. Build the issue genealogy

For every current comment, record:

| Current ID | First raised | Prior concern | Prior promise or disposition | Implemented evidence | Current reviewer assessment | Residual issue | Current action |
| --- | --- | --- | --- | --- | --- | --- | --- |

Classify the comment:

- **Closed:** the review team explicitly accepts the prior response; retain the evidence but do not relitigate it.
- **Residual:** the prior action was directionally correct but did not finish the argument.
- **Reopened:** a prior response created a new inconsistency, exposed a stronger benchmark, or was not implemented as claimed.
- **New:** the issue could not reasonably have been answered in the prior round.
- **Execution-only:** the science is accepted, but terminology, organization, figures, intuition, or presentation still obscures it.

Do not count comments. Identify which unresolved issue controls the editorial decision.

## 2. Read the decision hierarchy correctly

Separate recommendations from the editor's synthesis. Several minor-revision recommendations do not make the revision minor if the editor or associate editor identifies one unresolved contribution, validity, or welfare problem.

Write one sentence internally:

> The revision will become publishable only if the authors establish or correct ______.

Every major action in the round should contribute to that blank. Defer unrelated opportunities unless they are required to prevent a contradiction.

## 3. Separate results from execution

Maintain two workstreams:

### Results track

- factual correctness of the reviewer premise;
- equivalence or non-equivalence to the closest paper;
- endogenous decision ownership;
- missing benchmark, welfare metric, or stakeholder trade-off;
- result that is an artifact of an imposed parameter;
- assumption or extension that can overturn the central claim.

### Execution track

- terminology and construct labels;
- literature-review organization;
- proposition sequencing;
- mechanism explanations;
- managerial decision rules;
- tables, figures, and threshold illustrations;
- removal of overly technical or low-value main-text results.

Execution cannot rescue an incorrect or incremental result. A resolved results track can still fail if the manuscript does not let readers see the distinction.

## 4. Test the reviewer's factual premise

Before seeking “more novel results,” verify whether the claimed equivalence is correct:

1. write the closest paper's primitives, feasible choices, information structure, and equilibrium instrument;
2. write the revised paper's corresponding objects;
3. separate policy-induced changes from strategic choices;
4. recover the benchmark under the proposed restriction;
5. identify a parameter region or outcome in which the two mechanisms make different predictions;
6. compare signaling cost, feasibility, profit, and stakeholder outcomes using the same benchmark.

If the reviewer is correct, narrow the contribution or develop the minimum missing result. If the reviewer is not correct, demonstrate the distinction rather than asserting it.

## 5. Promote the right model and compress the rest

If a reviewer identifies a more natural decision structure, decide whether it belongs in the main model. Promote it when it is more institutionally credible and changes the main conclusion. Use the former main case as an appendix or intermediate feasibility step only if it remains analytically useful.

Compress analysis that is correct but hard to interpret:

- keep the managerial shape, switching condition, or finite candidate set in the main text;
- move exhaustive thresholds and low-value cases to the appendix;
- replace multiple staged propositions with one direct equilibrium characterization when adoption and operating decisions are jointly chosen;
- add figures only when they reveal regime boundaries or threshold ordering.

## 6. Convert results into decision rules

A late-round managerial discussion should answer the actual choices:

- whether the policy should be offered or mandated;
- who should control its intensity;
- whether the firm should adopt it;
- which strategic instrument is used;
- which stakeholder gains or loses;
- which institutional regime changes the recommendation.

State the objective before the recommendation. Identification, firm profit, transaction volume, success probability, and consumer surplus are different goals and may select different policies.

## 7. Reverify time-sensitive institutional facts

Practice can change between review rounds. Recheck current platform rules, policy names, funding formats, and implementation examples when they determine motivation or section placement. If a motivating practice disappears, distinguish historical evidence from current practice and reassess whether the analysis is a main application, a prospective policy, or an extension.

## 8. Acceptance-oriented release gate

Before resubmission, require:

- the controlling editorial hurdle is answered in the manuscript, not only the response letter;
- every prior promise is implemented, superseded explicitly, or disclosed as unresolved;
- no new analysis creates terminology, numbering, or contribution inconsistencies;
- the response contains only final prose: no `XXX`, drafting notes, “copy here,” tentative section placement, or unresolved alternatives;
- the abstract, introduction, literature review, results, implications, conclusion, and response letter use the same contribution language;
- added technical material has a clear decision or verification function.

Near acceptance, coherence has a higher expected value than an additional loosely connected result.
